# ChatGPT 26.715.72359 独立项目 Linux 适配计划

## 1. 目标与硬边界

项目根固定为：

```text
/data/projects/Local/codex_app/chatgpt_adapter
```

所有适配相关文件都必须位于该目录内，包括：

- 构建与安装代码。
- 版本配置和 bundle patch。
- 项目文档与运行记录。
- `ChatGPT.dmg` 项目内副本。
- 下载的 Electron 42.3.0 archive 与解包 runtime。
- native module 源码依赖、lockfile、编译目录和产物。
- 插件组合、sidecar 替代物、测试夹具。
- build、dist、cache、tmp 和 smoke 证据。

以下只允许作为外部工具或部署依赖，不得成为隐藏构建输入：

- `uv`、`pnpm`、`7z`、`file`、`tar`、`zstd` 等系统工具。
- 部署/运行时选择的系统 native `/data/bin/codex`。
- 初次迁移时只读参考的 `../codex_app/version_26.707.72221/`。

正式实现完成后，断开上级参考目录仍应能完成静态构建和验证。

## 4. Git 管理策略

### 跟踪内容

- `src/`、`scripts/`、`tests/`。
- `versions/` 下的版本配置、patch 和 marker。
- `pyproject.toml`、`uv.lock`、`package.json`、`pnpm-lock.yaml`。
- 输入、runtime、native、插件和发行包的 manifest/SHA256。
- `.ms` 规则、ADR、计划和 running docs。
- 小型 fixture；必要时单独评估是否进入 Git。

### 忽略内容

- DMG、Electron zip 和解包 runtime。
- pnpm/uv/npm/Electron cache。
- `node_modules`、native build 和 `.node` artifacts。
- app build、asar 解包目录、dist tar.zst。
- 日志、临时 profile、截图和 core dump。

### 大文件可追溯性

每个忽略的大文件都必须由已跟踪的 manifest 描述：

```json
{
  "name": "electron-v42.3.0-linux-x64.zip",
  "source": "官方 Electron release URL",
  "version": "42.3.0",
  "size": 0,
  "sha256": "待下载后填写"
}
```

普通 Git 不存储大文件。若未来必须共享不可重建的二进制，再由用户确认是否启用
Git LFS 或外部 artifact storage。

### 建议提交阶段

1. `chore(project): 初始化独立适配项目`
2. `build(runtime): 固定 Electron 42.3.0 输入`
3. `build(native): 增加 Electron 42.3.0 native modules`
4. `feat(adapter): 适配 26.715.72359 bundle`
5. `test(adapter): 增加静态与动态验收`
6. `docs(release): 记录发行包和部署结果`

每次只提交本阶段源码、配置和文档，不提交忽略的大文件。

## 5. 项目内环境隔离

新增 `scripts/项目环境.sh`，所有构建入口统一设置：

```text
UV_CACHE_DIR=<project>/.cache/uv
PNPM_STORE_DIR=<project>/.cache/pnpm-store
npm_config_cache=<project>/.cache/npm
ELECTRON_CACHE=<project>/.cache/electron
TMPDIR=<project>/tmp
```

pnpm 使用命令级 `--store-dir`，不修改全局 pnpm 配置。下载脚本的默认输出只能是
`inputs/` 或 `runtime/`，构建脚本默认输出只能是 `build/`、`dist/` 或
`native/**/artifacts/`。

## 6. 分阶段实施

### 阶段 A：初始化和输入本地化

1. 初始化独立 Git 仓库，默认分支 `main`。
2. 建立 Python `uv` 项目与 `src` layout。
3. 把当前 `../macos_pkg/ChatGPT.dmg` 复制到
   `inputs/chatgpt/26.715.72359/ChatGPT.dmg`，不移动或修改原文件。
4. 复制前后核对 SHA256，生成 `manifest.json` 和 `.sha256`。
5. 后续构建默认只读项目内 DMG。

验收：

- `git status --ignored` 确认 DMG 位于项目内但被忽略。
- 输入 manifest、SHA256 和 README 被 Git 跟踪。
- 构建配置中不存在 `../macos_pkg`。

### 阶段 B：Electron 42.3.0 runtime

1. 用项目内下载脚本获取官方 Electron 42.3.0 Linux x64 archive。
2. archive 写入 `runtime/electron/42.3.0/downloads/`。
3. 解包到同版本 `extracted/`，生成来源、大小、SHA256、ELF 和
   `Electron/42.3.0` manifest。
4. 不复用 `/data/opt/codex-gui` 或上级 `tmp/linux_desktop_runtime`。

验收：

- 下载和解包文件全部位于项目根内且被 Git 忽略。
- runtime manifest 被跟踪。
- Electron 为 Linux x86-64 ELF，版本精确为 42.3.0。

### 阶段 C：native modules

在 `native/electron-42.3.0/` 固定：

- `better-sqlite3 12.9.0`
- `node-pty 1.1.0`
- `@serialport/bindings-cpp 12.0.1`
- `node-hid 3.3.0`

实施：

1. 跟踪 `package.json`、`pnpm-lock.yaml` 和中文构建脚本。
2. 使用项目内 pnpm store、node_modules、build 和 artifacts。
3. 记录 Electron ABI、编译器、系统依赖和每个 artifact SHA256。
4. 用项目内 Electron 42.3.0 实际 `require()` 四个模块。

验收：

- 不从上级目录复制最终 `.node`。
- 四个 artifact 均为 Linux x86-64 ELF。
- `file`、依赖检查和 Electron 实际加载全部通过。

### 阶段 D：迁移通用构建框架

1. 只读参考 72221 的 `config/builder/patches/plugins/packaging/verify` 职责。
2. 在本项目 `src/chatgpt_adapter/` 重建通用实现，不从上级目录 import。
3. 版本差异下沉到 `versions/26.715.72359/version.toml` 和 `patches.py`。
4. 新增声明式 `resources.py`，处理 sidecar、portable resource 和禁用能力。
5. builder 保持编排职责，避免超过 600 行。

验收：

- 临时隐藏或重命名上级 72221 参考路径时，项目静态测试仍能运行。
- 所有默认路径由项目根计算，不含 `/data/opt/codex-gui` 等外部构建输入。

### 阶段 E：patch、资源与插件

Patch：

- 按新 bundle 重锚 9 个主进程和 8 个 worker Linux target。
- 重锚 1 个 Open with 合并补丁。
- 模型/Effort 和 Owl fallback 继续做语义断言。
- Spark 两个 workaround 先复现，再决定迁移或删除。

资源：

- `codex`：排除 macOS 二进制。
- `codex-code-mode-host`：Linux 替代或显式禁用。
- `codex_chronicle`：Linux 替代或 feature 安全降级。
- `rg`：项目内 Linux 资源或经过验证的系统路径策略。
- `cua_node`、`native/`：默认排除 macOS 内容。
- `default_app`：审计后决定 portable 或 exclude。

插件：

- 首轮目标仍为 `browser/chrome/latex/sites/deep-research/visualize`。
- `computer-use`、`record-and-replay` 默认不启用。
- 新 DMG 的 portable 文本资源与项目内 Linux binary overlay 分离。
- marketplace 必须与真实目录完全一致。

验收：

- 最终保留的 patch old/new marker 各精确命中一次。
- 每个顶层资源都有明确兼容结论。
- 原型无未知 Mach-O。
- 六个插件逐个通过 manifest 和最小加载检查。

### 阶段 F：构建、app-server 与 smoke

构建：

1. 同时提取 `app.asar` 和 `app.asar.unpacked`。
2. 清理 macOS artifact，安装项目内 native modules。
3. 应用版本 patch、资源和插件组合。
4. 用项目内 Electron runtime 生成原型。

app-server：

- 18765 已监听时连接外部 WebSocket。
- 未监听时由系统 native Codex 启动 stdio app-server。
- 当前系统 Codex 0.144.6 先做兼容测试；若缺新协议，明确最低版本，不打包
  macOS Codex。

smoke 全部使用项目内：

- `tmp/smoke/<case>/codex-home`
- `tmp/smoke/<case>/electron-user-data`
- `tmp/smoke/<case>/logs`
- `tmp/smoke/<case>/screenshots`

验收：

- Electron/native modules 加载成功。
- stdio 与 WebSocket initialize 成功。
- `thread/list`、`thread/resume`、`model/list`、`plugin/list`、`config/read`。
- 普通任务、续接任务和 Spark 条件测试。
- File Manager/VS Code/JetBrains target。
- `rg`、Code mode、Chronicle 按 capability 结论验收或安全降级。

### 阶段 G：发行与部署

1. 原型输出到 `build/ChatGPT-linux-from-macos/`。
2. tar.zst 输出到 `dist/`，二进制被 Git 忽略。
3. 跟踪 `dist/manifest.json` 和 `.sha256`。
4. 检查 tar 路径边界、关键入口、ELF、asar、插件和 Mach-O。
5. 部署动作单独执行，计划目标为：
   - `/data/opt/chatgpt-gui-26.715.72359`
   - `/data/bin/chatgpt_gui_26_715_72359`
   - `/data/bin/codex_gui_26_715_72359`
6. 部署不覆盖 72221 或稳定入口，安装过程不主动启动 GUI。

## 7. 完成定义

进入 `done_first_pass` 前必须满足：

- 项目内输入/runtime/native/build 链完整，不依赖上级旧版本或外部 runtime。
- Git 跟踪和忽略边界通过检查，没有误提交大文件或凭据。
- Electron 42.3.0 和四个 native modules 实际加载成功。
- patch、sidecar、插件和 Mach-O 验收通过。
- stdio/WebSocket 两条路径完成核心 RPC 和窗口 smoke。
- 发行包 manifest、条目数和 SHA256 已记录。
- 部署未覆盖旧版本；未执行的人工 GUI 或可选 sidecar 验收明确保留。
